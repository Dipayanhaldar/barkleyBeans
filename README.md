# Barkley Beans AI Studio

**A browser-first AI workspace for everyday questions, research, trend exploration, and content creation.**

Barkley Beans is a lightweight, client-side AI workspace built with **HTML5, CSS3, and vanilla JavaScript**. It brings several task-focused AI experiences into one responsive Progressive Web App (PWA), while letting each visitor use their own API key with a supported provider.

> **Architecture note:** This repository's current app is a static, browser-first frontend. It does not require an app-owned backend for the documented AI request flow. The visitor's browser sends requests to the selected provider, so API access, model availability, quotas, and provider policies apply.


Barkley Beans brings four focused AI workflows into one responsive, installable web app. It uses a **bring-your-own-key (BYOK)** model: visitors connect an API key from a supported AI provider and send requests directly from their browser to that provider.

## Features

### Four focused work modes

| Mode | What it helps with |
| --- | --- |
| **Everyday AI** | General questions, learning, explanations, planning, and brainstorming. |
| **Deep Research** | Structured investigations, key findings, evidence, counterpoints, limitations, and source review. |
| **Trend Radar** | Audience angles, content gaps, hooks, short-video ideas, and testable hypotheses. It does not provide a dedicated live social-trend feed. |
| **Content Studio** | Scripts, captions, titles, content plans, and creative briefs. It is not a full video editor or publishing platform. |

These modes use different instructions within the same application. They are not four independently trained AI models. Answers are generated by the provider and model selected by the visitor.

### Other capabilities

- Responsive desktop and mobile layout.
- Progressive Web App (PWA) manifest and service worker for an installable, cache-aware app shell.
- Visitor-owned API keys, with provider selection and model choice.
- Optional Google Search grounding for Google Gemini in Deep Research and Trend Radar; it is off by default.
- Local chat history in the browser.
- Browser-side PDF export for the active conversation.
- Calendar event helper with a Google Calendar template and downloadable `.ics` fallback.
- Footer shortcuts to this guide and the public GitHub repository.

## How to use the app

1. Open the [live website](https://barkley-beans-ai-studio.onrender.com/).
2. Select **Connect key** or the settings icon.
3. Create an API key in the developer console of a supported provider. A consumer app subscription/login is not necessarily an API key or API credit.
4. Select the provider that issued the key, paste the key, and choose a model available to that account.
5. Apply the key, choose one of the four modes, and enter a prompt.
6. Review the answer and any returned sources. Use the PDF or calendar actions when useful.
7. On a supported mobile browser, use the browser menu's **Install app** or **Add to Home screen** action to install the PWA.

### Providers in the current interface

The app's provider selector includes Google Gemini, OpenRouter, OpenAI, Anthropic Claude, Groq, DeepSeek, Mistral AI, xAI Grok, Perplexity, Cerebras, and Together AI.

Provider API access, model names, account eligibility, CORS behaviour, costs, quotas, and free-tier availability vary. A provider appearing in the selector does not guarantee that every model or key will work. Check the provider's current documentation and billing terms before sending requests. OpenRouter's free-model routing is subject to its availability and limits; it is not unlimited access.

## Privacy and security model

Barkley Beans is browser-first and does **not** currently operate its own AI proxy or app-owned chat database in the active PWA flow.

- **API keys:** stored in the current browser tab's `sessionStorage`, separately by provider. They are not intended to persist as server-side app credentials.
- **Chat history:** stored in the browser's `localStorage` on that device. It is not synced across devices by this app.
- **Prompts and context:** sent directly to the provider chosen by the visitor. The provider's own terms and data policies apply.
- **PDF and calendar actions:** prepared in the browser or handed to the calendar flow for the visitor to review.
- **No Barkley Beans login:** the current version does not include registration, an account database, or cross-device sync.

**Security notes**
- Never commit API keys, access tokens, `.env` files, passwords, service-role keys, or database credentials.
- Do not paste confidential, regulated, or client data unless you have approval and have checked the selected provider's terms.
- Clear keys and chat history when using a shared computer.
- Use provider-supported models and handle invalid-key, quota, network, CORS, and model-access errors based on the actual error returned.

## Architecture

```text
Visitor's browser
  ├── Barkley Beans UI (HTML, CSS, JavaScript)
  ├── Provider key in sessionStorage
  ├── Chat history in localStorage
  ├── Mode-specific prompt instructions
  ├── Browser-side PDF / calendar helpers
  └── HTTPS request ───────────────> Visitor-selected AI provider
                                      └── Answer / citations, when available
```

The active PWA is a static client-side application. Older experimental backend integrations are not part of the current documented request path.

## Running and deploying

### Run locally

No package installation or build step is required for the current static version.

1. Download or clone this repository.
2. Serve the `barkley-beans-studio/` directory with any static HTTP server, or open its `index.html` for a quick non-PWA check.
3. For proper PWA/service-worker testing, use `localhost` or an HTTPS origin. Browser behaviour may differ when opening a file directly with `file://`.
4. Connect a test API key and verify a simple prompt before testing other workflows. Avoid using production or sensitive data for development checks.

### Render deployment

The configured Render static site uses:

- **Repository:** `https://github.com/Dipayanhaldar/barkleyBeans`
- **Branch:** `main`
- **Publish directory:** `barkley-beans-studio`
- **Build step:** none required for this static HTML app; the service publishes the existing files.

Commits to the configured branch trigger deployment. After publishing, smoke-test the app URL, footer links, provider setup, one basic prompt, mobile layout, and the PWA installation flow. A deployment marked successful does not prove every provider API works, since provider credentials, permissions, quotas, and browser CORS policies vary.

## Testing and current limitations

The source includes client-side logic for the four modes, provider requests, local history, PDF export, calendar helpers, and PWA shell caching. Browser-level verification is still important after app or provider changes:

- Try a valid test key and a simple prompt for each provider you intend to support.
- Test errors for invalid keys, quota limits, unavailable models, timeouts, and CORS failures.
- Open the exported PDF and confirm it contains the expected conversation.
- Verify Calendar links and the `.ics` fallback.
- Test installation, refresh, offline fallback, and a fresh release on Android/Chrome and desktop browsers.
- Check responsive layout and external guide/repository links.

The app does not guarantee unlimited free AI usage, always-current model IDs, perfect results, or a live social-media trend feed. Verify important facts and citations.
